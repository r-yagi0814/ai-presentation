01 ─ Introduction

👋はじめに

この資料の目的

  • 「AIチャットは使ったことがあるけど、AIエージェントは何が違うのかよくわからない」を解消する
  • AIエージェントが今後の業務にどう関わってくるかを、専門用語なしでイメージできるようにする
  • 実際に使い始める前に知っておくべき注意点を整理する

対象者

  • ChatGPTやCopilotなどのAIチャットを使ったことがある方
  • 「AIエージェント」という言葉は聞いたことがあるが、詳しくは知らない方
  • 今後、業務でAIエージェントを使う可能性がある方
02 ─ Recap

💬おさらい：AIチャットとは

人がメッセージ（プロンプト）を送り、AIが1回の返信で応答する対話形式。
例：「この文章を要約して」「会議の議事録をまとめて」「アイデアを5つ出して」

特徴

  • 1問1答が基本：質問して答えが返ってくる。次に進むには人が次の指示を出す必要がある
  • 会話の外に出られない：ファイルを開いたり、ツールを操作したりはせず、テキストのやり取りの中で完結する
  • すべての判断・実行は人が行う：AIは提案するだけで、実際の作業（送信・保存・実行）は人がやる
03 ─ Limitations

🚧AIチャットの限界

課題具体例
一度にできることが1ステップ分「調べて→まとめて→資料化して」を毎回指示し直す必要がある
会話の外の作業ができないファイル操作・ツール実行・Web検索などは基本的にできない（機能拡張がない場合）
前提を毎回説明しがち会話が長くなると文脈を見失うことがある
実行は人任せAIが「こうすればいいですよ」と教えてくれても、実際に手を動かすのは人
💡 AIチャットは「優秀な相談相手」。実際に手足を動かして仕事を進めるのは人間側の役割だった
04 ─ What is an AI Agent

🤖AIエージェントとは

与えられた目的（ゴール）に対して、AIが自分で計画を立て、複数ステップを自律的に実行する仕組み。
単に質問に答えるのではなく、必要なツール（ファイル操作・コード実行・Web検索など）を自分で選んで使う。
人は最初に目的を伝えたら、あとは経過を確認しながら、必要なときだけ介入する。
イメージで理解する
AIチャット　　　 質問する → 1回答える → （次は人が指示）
AIエージェント　 目的を伝える → 計画する → 実行する → 確認する → 必要なら修正する → 完了
05 ─ Chat vs Agent

⚖️AIチャットとAIエージェントの違い

観点AIチャットAIエージェント
やり取りの単位1問1答目的達成までの一連のタスク
実行主体提案のみ、実行は人計画・実行までAIが行う
ツールの利用基本的になしファイル操作・コード実行・検索などを自律的に使用
継続性会話ごとにリセットされやすい目的に向かって複数ステップを継続的に遂行
人の役割都度指示を出す目的を設定し、結果をレビュー・承認する
代表例ChatGPT（Web版）、Copilot（Web版）Claude Code、Cursor（Agentモード）、Devin
06 ─ What Agents Can Do

🛠️AIエージェントでできること

具体例

  • コードを書き、実行し、エラーが出たら自分で修正する（ソフトウェア開発）
  • 複数のファイルを横断して調査し、レポートとしてまとめる
  • 与えられたタスクを小さいステップに分解し、順番に実行する
  • 作業の途中経過を人に報告し、判断が必要な場面だけ確認を取る

AIチャットとの組み合わせ方

  • ちょっとした質問・アイデア出し → AIチャットで十分
  • 複数ステップにまたがる作業・繰り返し発生する定型業務 → AIエージェントが向いている

08 ─ How Work Changes

🔄AIエージェントが変える働き方

1

「指示する」から「目的を伝える」へ：細かい手順ではなく、達成したいゴールを伝える形にシフトする

2

人の役割はレビュー・承認へ：すべてを自分でやるのではなく、AIの成果物を確認し、方向修正する役割が増える

3

繰り返し作業からの解放：定型的な調査・整理・下書き作成などをAIエージェントに任せられる

4

スピードと責任のバランス：速く進む分、最終的な判断・責任は引き続き人が持つ

09 ─ Things to Know

⚠️業務で使う前に知っておきたい注意点

注意点内容対策
ハルシネーションAIが自信満々に誤った情報を出すことがある重要な内容は必ずファクトチェックする
権限の与えすぎファイル削除・外部送信など、影響範囲の大きい操作を無制限に許可しない実行範囲・権限を最小限に設定する
情報漏洩社外秘の情報をそのまま入力しない会社のガイドラインに従い、入力してよい情報を確認する
ブラックボックス化「AIが全部やってくれる」に頼りすぎると、内容を理解しないまま進んでしまう節目ごとに成果物を確認し、内容を把握する習慣を持つ
破壊的な操作元に戻せない操作（削除・上書き・送信など）を自動で実行してしまう重要な操作の前には必ず確認を挟む設定にする
💡 AIエージェントは強力な分、「任せきりにしない」姿勢が今まで以上に大切になる
10 ─ GitHub Copilot at Work

🐙GitHub Copilotを業務で使う前に把握しておきたいこと

Copilotの特色

  • 普段使っているIDE（VS Code、JetBrains、Visual Studioなど）にプラグインとして導入できる。新しいツールに乗り換える必要がない
  • リポジトリ全体のコードを踏まえた提案を行う（コードベースの文脈を理解した補完）
  • コード補完（Completions）→ Chat → Agentモードと、段階的に自律性の高い機能が用意されている
  • GitHubのエコシステム（Issue・Pull Request・Actionsなど）と連携し、開発フロー全体をカバーできる
他サービスとの違い
観点GitHub CopilotChatGPTなどの汎用AIチャットCursor / Devin などのコーディングエージェント
主戦場使い慣れたIDEの中独立したチャット画面専用エディタ／独立した実行環境
得意なことコーディング全般への特化支援文章作成・アイデア出しなど汎用タスクコードベース全体の自律的な編集・開発の自動化
開発ワークフローとの連携Issue/PR/Actionsなど開発フロー全体と密接に統合基本的になしツールにより異なる
導入のハードル既存環境にプラグイン追加のみで低いブラウザで完結し低い新しいエディタ・環境への移行が必要な場合がある
💡 「既存の開発環境に自然に溶け込む」ことがGitHub Copilotの最大の特色。新しいツールを覚える負担が少ない一方、GitHubのエコシステムを前提とした設計になっている
11 ─ Rules & Skills

📐もう一歩進んだ概念：ルールとスキル

ルール（Rules）とは

  • プロジェクトやチームの前提・規約をファイルに書いておき、AIエージェントに常に守らせる仕組み
  • 毎回同じ説明をしなくても、AIが自動的にそのプロジェクトのルールに従って動くようになる
  • 例：CLAUDE.md、.github/copilot-instructions.md、.cursor/rules

スキル（Skills）とは

  • よく使う作業手順をあらかじめテンプレート化し、必要なときに呼び出して再利用できる仕組み
  • 「毎回同じ指示を書き直す」手間をなくし、チーム内で作業のやり方を統一できる
  • 例：スラッシュコマンド、カスタムGPTs、Copilot拡張機能
概念役割具体例
ルール（Rules）プロジェクト・チームの前提や規約をAIに常時適用させるCLAUDE.md、copilot-instructions.md、.cursor/rules
スキル（Skills）特定の作業手順をテンプレート化し、必要なときに呼び出すスラッシュコマンド、カスタムGPTs、Copilot拡張機能
💡 チーム全体で同じ基準・手順にそろえられ（属人化を防止）、繰り返し作業を効率化できる。AIエージェントに「何を守るべきか」「どう動くべきか」を事前に伝えておくことで、任せられる範囲が広がる
12 ─ Summary

✅まとめ

1

AIチャット＝1問1答の相談相手、AIエージェント＝目的達成まで自律的に動く実行者

2

AIエージェントはツールを使い、複数ステップを自分で計画・実行できる点が最大の違い

3

便利になる一方で、権限管理・ファクトチェック・情報漏洩対策など、任せきりにしない姿勢が重要

4

まずは小さなタスクから試し、少しずつ活用範囲を広げていくのがおすすめ

AIエージェントは「使ったことがないから難しそう」なものではなく、AIチャットの延長線上にある技術。
今のうちに違いと注意点を理解しておくことで、今後の業務での活用がスムーズになる。
