## はじめに

### この資料の目的
- 「AIチャットは使ったことがあるけど、AIエージェントは何が違うのかよくわからない」を解消する
- AIエージェントが今後の業務にどう関わってくるかを、難しい専門用語なしでイメージできるようにする
- 実際に使い始める前に知っておくべき注意点を整理する

### 対象者
- ChatGPTやCopilotなどのAIチャットを使ったことがある方
- 「AIエージェント」という言葉は聞いたことがあるが、詳しくは知らない方
- 今後、業務でAIエージェントを使う可能性がある方

---

## おさらい：AIチャットとは

### 基本的な使い方
- 人がメッセージ（プロンプト）を送り、AIが1回の返信で応答する対話形式
- 例：「この文章を要約して」「会議の議事録をまとめて」「アイデアを5つ出して」

### 特徴
- **1問1答が基本**：質問して、答えが返ってくる。次に進むには人が次の指示を出す必要がある
- **AIは会話の外に出られない**：ファイルを開いたり、ツールを操作したりはせず、テキストのやり取りの中で完結する
- **すべての判断・実行は人が行う**：AIは提案するだけで、実際の作業（送信・保存・実行）は人がやる

---

## AIチャットの限界

### よくあるつまずき
| 課題 | 具体例 |
|------|--------|
| 一度にできることが1ステップ分 | 「調べて→まとめて→資料化して」を毎回指示し直す必要がある |
| 会話の外の作業ができない | ファイル操作・ツール実行・Web検索などは基本的にできない（機能拡張がない場合） |
| 前提を毎回説明しがち | 会話が長くなると文脈を見失うことがある |
| 実行は人任せ | AIが「こうすればいいですよ」と教えてくれても、実際に手を動かすのは人 |

> **ポイント**: AIチャットは「優秀な相談相手」。実際に手足を動かして仕事を進めるのは人間側の役割だった

---

## AIエージェントとは

### 定義
- 与えられた目的（ゴール）に対して、AIが**自分で計画を立て、複数ステップを自律的に実行する**仕組み
- 単に質問に答えるのではなく、必要なツール（ファイル操作・コード実行・Web検索など）を**自分で選んで使う**
- 人は最初に目的を伝えたら、あとは経過を確認しながら、必要なときだけ介入する

### イメージで理解する
```
AIチャット：　質問する → 1回答える → （次は人が指示）
AIエージェント：目的を伝える → 計画する → 実行する → 確認する → 必要なら修正する → 完了
```

---

## AIチャットとAIエージェントの違い

| 観点 | AIチャット | AIエージェント |
|------|-----------|----------------|
| やり取りの単位 | 1問1答 | 目的達成までの一連のタスク |
| 実行主体 | 提案のみ、実行は人 | 計画・実行までAIが行う |
| ツールの利用 | 基本的になし | ファイル操作・コード実行・検索などを自律的に使用 |
| 継続性 | 会話ごとにリセットされやすい | 目的に向かって複数ステップを継続的に遂行 |
| 人の役割 | 都度指示を出す | 目的を設定し、結果をレビュー・承認する |
| 代表例 | ChatGPT（Web版）、Copilot（Web版） | Claude Code、Cursor（Agentモード）、Devin |

---

## AIエージェントでできること

### 具体例
- コードを書き、実行し、エラーが出たら自分で修正する（ソフトウェア開発）
- 複数のファイルを横断して調査し、レポートとしてまとめる
- 与えられたタスクを小さいステップに分解し、順番に実行する
- 作業の途中経過を人に報告し、判断が必要な場面だけ確認を取る

### AIチャットとの組み合わせ方
- ちょっとした質問・アイデア出し → **AIチャット**で十分
- 複数ステップにまたがる作業・繰り返し発生する定型業務 → **AIエージェント**が向いている

## 代表的なAIエージェントツール

| ツール | 概要 | 主な用途 |
|--------|------|---------|
| **Claude Code** | CLI（コマンドライン）で動くAnthropic製の開発エージェント | コーディング・ファイル操作・自動化タスク |
| **Cursor（Agentモード）** | AIペアプログラマーとして動作するエディタ | コードベース全体の編集・リファクタリング |
| **Devin** | 自律的にコードを書き・テストし・修正するAIエンジニア | ソフトウェア開発の自動化 |
| **GitHub Copilot（Agent機能）** | コード補完に加え、複数ファイルにまたがる変更を自律実行 | 開発支援 |

> 現時点ではコーディング領域での活用が先行しているが、今後は資料作成・データ分析・業務システム操作など、他領域への広がりが見込まれている

## AIエージェントが変える働き方

### 変化のポイント
1. **「指示する」から「目的を伝える」へ**：細かい手順ではなく、達成したいゴールを伝える形にシフトする
2. **人の役割はレビュー・承認へ**：すべてを自分でやるのではなく、AIの成果物を確認し、方向修正する役割が増える
3. **繰り返し作業からの解放**：定型的な調査・整理・下書き作成などをAIエージェントに任せられる
4. **スピードと責任のバランス**：速く進む分、最終的な判断・責任は引き続き人が持つ

## 業務で使う前に知っておきたい注意点

### リスクと対策
| 注意点 | 内容 | 対策 |
|--------|------|------|
| ハルシネーション | AIが自信満々に誤った情報を出すことがある | 重要な内容は必ずファクトチェックする |
| 権限の与えすぎ | ファイル削除・外部送信など、影響範囲の大きい操作を無制限に許可しない | 実行範囲・権限を最小限に設定する |
| 情報漏洩 | 社外秘の情報をそのまま入力しない | 会社のガイドラインに従い、入力してよい情報を確認する |
| ブラックボックス化 | 「AIが全部やってくれる」に頼りすぎると、内容を理解しないまま進んでしまう | 節目ごとに成果物を確認し、内容を把握する習慣を持つ |
| 破壊的な操作 | 元に戻せない操作（削除・上書き・送信など）を自動で実行してしまう | 重要な操作の前には必ず確認を挟む設定にする |

> **ポイント**: AIエージェントは強力な分、「任せきりにしない」姿勢が今まで以上に大切になる

## GitHub Copilotを業務で使う前に把握しておきたいこと

### Copilotの特色
- 普段使っているIDE（VS Code、JetBrains、Visual Studioなど）にプラグインとして導入できる。新しいツールに乗り換える必要がない
- リポジトリ全体のコードを踏まえた提案を行う（コードベースの文脈を理解した補完）
- コード補完（Completions）→ Chat → Agentモードと、段階的に自律性の高い機能が用意されている
- GitHubのエコシステム（Issue・Pull Request・Actionsなど）と連携し、開発フロー全体をカバーできる

### 他サービスとの違い
| 観点 | GitHub Copilot | ChatGPTなどの汎用AIチャット | Cursor / Devin などのコーディングエージェント |
|------|----------------|------------------------------|----------------------------------------------|
| 主戦場 | 使い慣れたIDEの中 | 独立したチャット画面 | 専用エディタ／独立した実行環境 |
| 得意なこと | コーディング全般への特化支援 | 文章作成・アイデア出しなど汎用タスク | コードベース全体の自律的な編集・開発の自動化 |
| 開発ワークフローとの連携 | Issue/PR/Actionsなど開発フロー全体と密接に統合 | 基本的になし | ツールにより異なる |
| 導入のハードル | 既存環境にプラグイン追加のみで低い | ブラウザで完結し低い | 新しいエディタ・環境への移行が必要な場合がある |

> **ポイント**: 「既存の開発環境に自然に溶け込む」ことがGitHub Copilotの最大の特色。新しいツールを覚える負担が少ない一方、GitHubのエコシステムを前提とした設計になっている

## もう一歩進んだ概念：ルールとスキル

### ルール（Rules）とは
- プロジェクトやチームの前提・規約をファイルに書いておき、AIエージェントに常に守らせる仕組み
- 毎回同じ説明をしなくても、AIが自動的にそのプロジェクトのルールに従って動くようになる
- 例：Claude Codeの `CLAUDE.md`、GitHub Copilotの `.github/copilot-instructions.md`、Cursorの `.cursor/rules`

### スキル（Skills）とは
- よく使う作業手順をあらかじめテンプレート化し、必要なときに呼び出して再利用できる仕組み
- 「毎回同じ指示を書き直す」手間をなくし、チーム内で作業のやり方を統一できる
- 例：スラッシュコマンド、カスタムGPTs、Copilot拡張機能

### 比較

| 概念 | 役割 | 具体例 |
|------|------|--------|
| ルール（Rules） | プロジェクト・チームの前提や規約をAIに常時適用させる | CLAUDE.md、copilot-instructions.md、.cursor/rules |
| スキル（Skills） | 特定の作業手順をテンプレート化し、必要なときに呼び出す | スラッシュコマンド、カスタムGPTs、Copilot拡張機能 |

### なぜ重要か
- チーム全体で同じ基準・手順にそろえられる（属人化を防げる）
- 繰り返し発生する定型作業を効率化できる
- AIエージェントに「何を守るべきか」「どう動くべきか」を事前に伝えておくことで、任せられる範囲が広がる

---

## まとめ

### 要点の整理
1. AIチャット＝1問1答の相談相手、AIエージェント＝目的達成まで自律的に動く実行者
2. AIエージェントはツールを使い、複数ステップを自分で計画・実行できる点が最大の違い
3. 便利になる一方で、権限管理・ファクトチェック・情報漏洩対策など、任せきりにしない姿勢が重要
4. まずは小さなタスクから試し、少しずつ活用範囲を広げていくのがおすすめ

### 結論
- AIエージェントは「使ったことがないから難しそう」なものではなく、AIチャットの延長線上にある技術
- 今のうちに違いと注意点を理解しておくことで、今後の業務での活用がスムーズになる
